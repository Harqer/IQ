## Deterministic audit -> remediation -> re-audit loop (every phase)

1. Read the **pinned upstream code and official documentation first**; cite exact equation/function/configuration with immutable revision where feasible.
2. Read **all actual IQ caller/callee files, configs, tests and checkpoints**, not inferred framework behavior.
3. Record discrepancy as proved / no issue / weak / N/A, including file/path/method, severity, invariant, fallback/logging requirements and an acceptance test.
4. Edit all affected production, test, and spec files through GitHub; preserve canonical Mamba3 MIMO and source-compatible weights. No silent SISO/CPU substitute or mocked production state.
5. Run compile + full CPU suite. Independently re-audit new/previous findings and re-run until green or explicitly record remaining code blocker. Avoid editing during a CI run except to remediate an observed failure.
6. Advance to the next **coding** phase once its source-grounded CPU/repo gates pass, even if final hardware gates remain unexecuted. H200 is the last step.

## Source reference: Per-Head Muon

- [Kimi K3 official technical report](https://arxiv.org/html/2607.24653v2) §2.5 describes treating Q/K/V momentum **per attention head** for Muon orthogonalization, rather than orthogonalizing the concatenated projection.
- [PyTorch `torch.optim._muon` source](https://github.com/pytorch/pytorch/blob/main/torch/optim/_muon.py) supplies the official momentum `buffer.lerp_(grad, 1-momentum)`, quintic Newton–Schulz coefficients `(3.4445,-4.7750,2.0315)`, and `adjust_lr_fn="match_rms_adamw"` scaling `0.2*sqrt(max(rows,cols))`.
- [Independent third-party K3 implementation](https://github.com/pablo-reyes8/kimi-k3-pytorch/blob/bbd79cb8cc964900812fdeb661e84f41d0fe27d9/training/optimizer/per_head_muon.py) corroborates split-head transforms and head-isolation tests but is **not** claimed as upstream Kimi owner code.
- IQ `PerHeadMuon` keeps original full `nn.Parameter` tensors for checkpoint/loading and splits momentum only during each independent headwise update; `classify_parameters` uses actual module classes/shape rather than speculative name-only assignments. Optimizer schema v2 preserves head layouts and fails closed on incompatible v1 checkpoint conversion.
- No fallback silently demotes headwise Q/K/V to conventional Muon after an optimizer error. The explicit `OptimizerConfig(per_head_qkv=False)` is a controlled noncanonical experiment only.

## Failure and logging contract for subsequent runtime phases

- A genuine MIMO, CSA/HCA, vision, or decoding-kernel failure is surfaced as a typed/traceable error. **Dense teacher/control is an explicitly selected comparison mode**, not an automatic error fallback that produces model outputs under a different architecture.
- Failure fallback may retry the same authorized operation only when the input, state and side effects can be safely replayed; do not retry mutated recurrent-cache states or external tool calls blindly.
- Emit structured model, training and tool events with run ID, session scope, model revision/config fingerprint, selected layer/route, error code, elapsed steps and resource counters. Never log raw user prompts, private files or secrets by default.
- Stage snapshots/checkpoints atomically and retain enough immutable provenance to reproduce errors.
- Fail closed when process-group membership, tokenizer IDs, checkpoint schemas, tool privileges, or cache ownership are unverified.
